# Skeptical reviewer: novelty and evidence attack

This is an internal pre-submission stress test, not a response letter. `VALID` means the objection is supported by current repo/prior art; `PARTIALLY_VALID` means it captures a real limitation but overstates it; `NOT_SUPPORTED` means current evidence does not substantiate the attack.

| Reviewer objection | Assessment | Why / evidence needed |
|---|---|---|
| “This is a wrapper around an existing LIF model.” | PARTIALLY_VALID | The active computational case uses an existing model/backend; novel neural dynamics are not claimed. But the repository implements additional study support, approval, QC/provenance and ranking paths. A clean architecture and direct comparison must show these are more than superficial wrappers. No independent operator run is complete yet. |
| “FlyBrainLab already provides a Drosophila workbench.” | VALID | FlyBrainLab is a close domain-specific platform for anatomy/data integration and executable circuits. Authors need a versioned, feature-level software comparison and a narrow statement that distinguishes exploratory circuit modeling from the support-gated study contract. The 2021 paper cannot establish undocumented current software behavior. |
| “Connectome-based prioritization has already been done.” | VALID | Pospisil et al. use connectome-informed causal estimation to identify dominant circuits and testable hypotheses. Do not claim ranking/prioritization itself as new. Explain and evaluate how Workbench's workflow decision differs from their estimator and scientific objective. |
| “Evidence-aware, abstaining virtual experiments are already proposed.” | VALID | PRAXIS-VirtualCell's 2026 arXiv preprint describes evidence-aware execution, biological contracts, abstention and traceable virtual experiments. It is not peer-reviewed and targets virtual cells, not fly connectomes, but it defeats a broad “first trustworthy virtual experiment system” claim. Compare directly and state dates/status. |
| “StudySpec and automated neural experiment workflows are old.” | VALID | Mozaik integrates experiment/stimulation specification, execution, storage, analysis and visualization. StudySpec alone is not novel. The claimed difference must be the enforced support/approval semantics, with tests and evidence that they prevent invalid runs. |
| “Provenance, hashes and reproducibility are generic engineering.” | VALID | AiiDA, Snakemake, DataJoint and neuroscience-specific workflows establish strong prior art. The paper can report provenance as a quality feature, not as a scientific novelty. Demonstrate end-to-end independent reproduction and failure reproduction. |
| “Your evidence/capability gates do not discriminate on the benchmark.” | VALID | Development evidence reports both gates pass all 106 registered cases. Their incremental effect cannot be estimated from this benchmark. Add separate prespecified cases where support truly fails or requires review, without leaking held-out cases or changing the locked benchmark. |
| “Full Workbench does not beat effect-only.” | VALID | In the frozen 74-case development ablation, AP is 0.6259 vs 0.6592 and P@5 is 0.80 for both. Remove superiority language. A useful workflow may remain, but needs an outcome measure other than this ranking comparison. |
| “Random baseline is a straw man; no strong baseline comparison.” | PARTIALLY_VALID | Random is a negative reference, while effect-only is more informative and currently matches/beats the full score. The proposed final comparator set still requires owner approval. Do not run or choose comparators as part of this novelty task; later evaluate only the predeclared approved set with common denominator. |
| “This is not a true experiment-planning system; it just outputs a score.” | PARTIALLY_VALID | Code includes StudySpec, support assessment, approval, adapters, jobs, manifests and selection, but the active benchmark tests a narrow frozen score, not end-to-end researcher question-to-protocol utility. Provide a reproducible end-to-end demonstration and state which intake steps are optional/draft-only. |
| “The manuscript conflates Drosophila model output with Parkinson's disease biology.” | NOT_SUPPORTED by the active scope; risk must remain controlled | Active scope explicitly excludes Parkinson validation, disease claims, and firing-to-behavior conversion. Preserve these exclusions in title, abstract, figures and discussion; historical neural-disease tracks must not be merged into active evidence. |
| “No biological or wet-lab evidence supports the claimed utility.” | VALID | Current evidence is computational/software only. Add independent biological case review and prospective/wet-lab validation for biological utility; otherwise explicitly call it a computational workbench and make no biological efficacy claims. |
| “It has not been independently reproduced.” | VALID | Owner same-operator reproduction is not independent. Need the named second operator's clean environment, exact inputs/revision, both success and failure/QC records, and verifier PASS before making that claim. |
| “A successful software test suite proves scientific validity.” | NOT_SUPPORTED as a claim; guard against it | Tests show implementation contracts behave as coded, not that mappings or model outputs are biologically true. Report software validation and biological validation separately. |

## Reviewer recommendation implied by this audit

Do not submit with “new connectome-based prioritization method,” “first evidence-aware virtual experiment system,” or “biologically useful candidate selection” as the primary novelty. A narrower software/methods paper is defensible only if claims match the code, the close systems are compared fairly, reproducibility is independently demonstrated, and manuscript limitations prominently disclose the non-discriminative gates and non-superiority to effect-only on development data.
