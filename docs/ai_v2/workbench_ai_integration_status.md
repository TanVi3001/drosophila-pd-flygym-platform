## What changed in this increment

- Added exact, review-aware mapping lookup in `mapping_resolution.py`. It does
  not use fuzzy matching, aliases, inferred left/right identity, or model-made
  IDs. Even a single result is presented for explicit human selection.
- A human-selected record is bound to the draft with immutable mapping ID,
  version, and record hash. It carries both target/input IDs and reviewed
  readout IDs from that record; neither is copied into or generated by the AI
  draft. Historical records without readout IDs retain their old hashes, but
  are not selectable for this AI workflow until explicitly reviewed/updated.
- Workbench support assessment and job materialization now check any pinned
  mapping version/hash. The run config and its manifest retain mapping identity.
- Added an explicit workflow facade for draft creation, approval, job submission,
  run/cancel/resume and status. It reuses the Workbench's existing approval and
  worker gates; it does not give the AI shell or autonomous approval.
- Run manifests can now include an allowlisted AI provenance record: evidence
  IDs and their hash, provider/model IDs, prompt version and corpus/log/output
  hashes when supplied. Prompt bodies, protocol text and credentials are not
  admitted to that record.
- Added an assistant evaluation scorer for development-only bundles and a
  synthetic workflow demo with a report chart and three fail/allow paths.
- Added HTTP endpoints for mapping resolution, explicit mapping selection,
  AI-draft persistence, human approval, job submission and run/status, backed by
  the same Workbench service. Staging routes require a bearer token.
- Added a localhost-only Docker Compose staging profile with persistent state,
  non-root/read-only container settings, health/readiness checks and a setup
  runbook. The API token is required in staging; the provider remains off by
  default.
- Added a strict frozen-corpus JSONL loader and deterministic local BM25-style
  retrieval. It verifies the SHA-256 before serving, enforces DEVELOPMENT-only
  partition plus source allow/deny and access-class checks, rejects unknown or
  duplicate fields/IDs, and logs query hashes rather than raw query text.
- Added manifest creation/validation tooling that never overwrites an existing
  freeze. Provider sharing is opt-in, separated for corpus excerpts and protocol
  text, and bound to the exact provider model ID and endpoint.
- Connected evidence-conditioned generation to the optional OpenAI-compatible
  provider and authenticated RAG status/retrieve/draft API routes. No-hit queries
  abstain without a provider call; unsupported citations are removed; drafts are
  persisted with corpus/retrieval/output hashes and remain unapproved.
- Disabled the legacy ungrounded provider endpoint by default and updated the
  staging browser page to expose RAG readiness, retrieval-only preview, and
  evidence-conditioned draft actions. The provider still defaults off.

## Safe demo

### Follow-up: review-gated synthetic path (2026-10-07)

Added `scripts/run_ai_v2_review_gated_demo.py` and
`docs/ai_v2/review_gated_demo.md`. This path prepares a local synthetic protocol,
retrieved fixture evidence, a deterministic draft envelope, and an editable
human-review form. Finalization requires the operator's own edits and exact
fixture mapping ID/version/hash, then uses the existing mapping resolver and
Workbench support assessment. It stops at
`SYNTHETIC_STUDYSPEC_VALIDATED_AWAITING_RESEARCHER_APPROVAL`; it does not record
an approval, submit a job, or run a simulator. The “draft” is not an LLM output;
all evidence and IDs are invented fixtures. A prepare session was generated
locally; finalization is pending the operator's human review.

The three-arm comparator's structural-only invocation on 2026-10-07 returned
12 cases, `DRAFT_NOT_APPROVED`, `live_run_approved=false`, and
`HELDOUT_STATUS=LOCKED_NOT_RUN`. Therefore comparator code is present, but no
real Gemini comparison or AI-quality metrics have been collected.

Run from this repository in its Python environment:

```powershell
python scripts/run_ai_v2_workbench_demo.py --output-dir results/ai_v2_workbench_demo_synthetic
```

The target directory must be empty. The script never reads the 74 Shiu labels,
32 held-out labels, external sealed labels, or FlyWire model inputs. It does not
call a hosted LLM or a biological simulator. The output writes
`demo_summary.json`, `workbench_report.json`, `synthetic_workbench_report.png`,
`retrieval.jsonl`, and `sha256.json`.

To score a future human-approved assistant evaluation bundle:

```powershell
python scripts/evaluate_ai_v2_assistant.py --input <approved-development-bundle.json> --output <metrics.json> --k 5
```

The evaluator rejects any partition other than `DEVELOPMENT`. A single-owner
demo uses `evaluation_mode: OWNER_REVIEWED_DEMO`, `owner_demo: true`, and
`independent_review_claim: false`; its output is labeled non-independent. The
publication-oriented `APPROVED_DEVELOPMENT` mode still needs two distinct human
reviewers. Both modes require frozen corpus, rubric and protocol hashes, approved
corpus/rubric states, provider/privacy approval, and per-case outputs for
`manual_template`, `llm_no_retrieval`, and `llm_rag`.
Every system must explicitly return either `COMPLETED` or `ABSTAINED` for every
case so coverage and metric denominators are comparable. Human claim annotations
are required for unsupported-claim rate; an LLM judge is not used. Owner-demo
claim annotations must identify the sole owner reviewer.

## Metrics and their denominators

- `Recall@K`, `Precision@K`: macro-average over cases with at least one
  human-approved gold evidence chunk.
- `Citation Precision`: correct `(source_id, chunk_id)` citations divided by
  all citations; null when the system cites nothing.
- `Required-field exact accuracy`: exact matching required fields divided by
  all required fields across the complete case set.
- Missing-field detection: micro precision/recall/F1 over the human gold list.
- Unsupported-claim rate: human-adjudicated unsupported claims divided by
  determinate human-reviewed claims; uncertain annotations are shown separately.
- Coverage and schema-valid rate: completed/schema-valid cases divided by all
  frozen development cases.

Metrics have meaning only after the question set, acceptable answers, citation
rules, rubric, providers/prompts and comparator outputs are frozen. Do not tune
on this same set and then present it as independent evaluation.
