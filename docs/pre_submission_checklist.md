# Pre-submission checklist

Do not mark complete by assumption; attach evidence at submission review.

- [ ] Title and abstract match the actual computational methods scope.
- [ ] Contribution statement is distinct from FlyWire, Shiu's model, FlyGym/NeuroMechFly and generic workflow/provenance prior art.
- [ ] Novelty matrix updated after focused literature review, including candidate prioritization/virtual-screening systems.
- [ ] Introduction, Methods and Discussion define scope, limitations and human decision boundary.
- [ ] Development results reproduce from frozen artifacts and are labeled `DEVELOPMENT`.
- [ ] Final evaluation protocol and comparator set receive explicit owner approval before any held-out execution.
- [ ] Held-out result is reported only after authorized one-time execution; otherwise state pending/not run.
- [ ] Owner reproduction and independent second-operator reproduction are reported as different evidence classes.
- [ ] Software tests, QC/failure states, provenance and artifact hashes are recorded.
- [ ] Software availability, data availability, source revision, dependency/environment and license/citation metadata are complete.
- [ ] Figures 1–4 use verified development/software evidence; Figure 5 uses held-out outputs only after approval.
- [ ] Limitations include retrospective label meaning, small split, LIF readout, non-discriminative gates, no behavioral/wet-lab/PD validation.
- [ ] Claim audit excludes MN9 firing-to-behavior equivalence and biological intervention efficacy.
- [ ] Scientific case review has a genuine expert record; otherwise mark pending and narrow claims.
- [ ] Clean release branch/worktrees, checksums, README and reproduction instructions are independently checked.
- [ ] Manuscript tables/figures match frozen machine-readable records and contain no held-out leakage.
